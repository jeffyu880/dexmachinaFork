# Training Arguments Reference for `train_rl_games.py`

This document explains all the arguments used in the training command in `train_rl.sh`.

## Quick Summary

This command trains a bimanual dexterous manipulation agent using:
- **4096 parallel environments** on GPU
- **Imitation learning** from retargeted human demos
- **Contact-based rewards** to maintain hand-object interaction
- **Curriculum learning** with adaptive difficulty progression
- **Hybrid action space** combining absolute and residual control
- **Object actuation** to learn manipulation with active object control

---

## Argument Categories

### 1. **Environment & Parallelization**

```bash
-B 4096                    # Batch size: 4096 parallel environments on GPU
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `-B` / `--num_envs` | int | 4096 | Number of parallel simulation environments (GPU batch size) |

**Impact:** More envs = faster data collection but higher GPU memory usage. 4096 is large; adjust down (256, 512, 1024) if out of memory.

---

### 2. **Demo Data & Retargeting**

```bash
--clip box-30-230          # Which ARCTIC demo clip to load
--retarget_name para       # Which retargeted trajectory variant to use
--use_retarget_contact     # Use contact points from retargeted demo as supervision
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--clip` | str | `box-30-230` | Demo clip: object=`box`, frames 30–230, default subject s01, clip 01 |
| `--retarget_name` | str | `para` | Load retargeted trajectory: `assets/retargeted/<hand>/s01/box_use_01_*_para.pt` |
| `--use_retarget_contact` | flag | ON | Use contact points from retargeted demo as reward targets |

**Note:** The retargeted trajectory `para.pt` must exist (generated by `parallel_retarget.py --save_name para --save`).

---

### 3. **Observation & Action Space**

```bash
-obf -obt                  # Observe contact force & tip distance
-am hybrid                 # Hybrid action mode
--hybrid_scales 0.1 1.0    # Scaling for hybrid actions
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `-obf` / `--observe_contact_force` | flag | ON | Include contact forces in agent observation |
| `-obt` / `--observe_tip_dist` | flag | ON | Include fingertip distances in observation |
| `-am` / `--action_mode` | str | `hybrid` | Action space: `residual` (delta), `absolute` (target), `hybrid` (both) |
| `--hybrid_scales` | float list | `[0.1, 1.0]` | Scale factors for hybrid actions (residual scale, absolute scale) |

**Action modes:**
- `absolute`: direct joint position targets
- `residual`: delta from current state
- `hybrid`: mix of both (0.1× residual + 1.0× absolute)

---

### 4. **Reward Configuration**

```bash
-imi 0.3                   # Imitation reward weight
-bc 0.3                    # Behavior cloning reward weight
-con 3                     # Contact reward weight
--contact_beta 10          # Contact reward scaling parameter
--task_rew_betas 10 1 5    # Task reward betas: [obj_pos, obj_rot, obj_arti]
--action_penalty 0.01      # Penalty for large actions (smoothness)
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `-imi` / `--imi_rew_weight` | float | 0.3 | Imitation reward: match retargeted joint positions |
| `-bc` / `--bc_rew_weight` | float | 0.3 | Behavior cloning reward: additional imitation signal |
| `-con` / `--contact_rew_weight` | float | 3.0 | Contact reward: maintain hand-object interaction |
| `--contact_beta` | float | 10.0 | Scaling parameter for contact distance calculations |
| `--task_rew_betas` | float list | `[10, 1, 5]` | Task reward scales: object position (10), rotation (1), articulation (5) |
| `--action_penalty` | float | 0.01 | Penalty per action: reduces jerky/large movements |

**Reward equation (simplified):**
```
Total = 0.3 × imitation_reward
      + 0.3 × behavior_cloning_reward
      + 3.0 × contact_reward
      + task_reward (weighted by betas)
      - 0.01 × action_norm
```

---

### 5. **Training Hyperparameters**

```bash
--max_epochs 10            # Total training epochs
--horizon 16               # Steps per episode
--learning_rate 0.0003     # Policy network learning rate
--save_freq 500            # Checkpoint save frequency (iterations)
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--max_epochs` | int | 10 | Total number of training epochs (passes through data) |
| `--horizon` | int | 16 | Episode length (steps before reset) |
| `-lr` / `--learning_rate` | float | 0.0003 | PPO policy network learning rate |
| `--save_freq` | int | 500 | Save checkpoint every N iterations |

**Episode length:** 16 steps ≈ 0.27 seconds in real time.
**Total training:** 4096 envs × 16 steps × 10 epochs = 655,360 environment steps.

---

### 6. **Curriculum Learning (Progressive Difficulty)**

```bash
--curr_schedule uniform    # Gain progression schedule: uniform over time
--wait_epochs 100          # Wait 100 epochs before starting curriculum
--fixed_mode uniform       # Fixed curriculum mode: uniform distribution
--gain_mode all            # Which gains to adjust: all (kp, kv, force_range)
--uniform_mode slow        # Uniform curriculum speed: slow progression
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--curr_schedule` | str | `uniform` | Schedule type: `fixed` (no progression), `exp` (exponential), `uniform` (linear) |
| `--wait_epochs` | int | 100 | Don't adjust gains for first 100 epochs |
| `--fixed_mode` | str | `uniform` | Mode when schedule=fixed: `exp`, `lin`, `uniform` |
| `--gain_mode` | str | `all` | Which gains to adjust: `all` (kp+kv+force), `kpkv`, `fr` (force only) |
| `--uniform_mode` | str | `slow` | Speed of uniform progression: `slow`, `fast` |

**Gain ranges (defaults, can adjust):**
- `--kp_init 80` → `--upper_ratios 0.9` → max kp increases 90% over training
- `--kv_init 5` → `--lower_ratios 0.8` → min kv stays at 80% of init
- `--force_range_init` → adjusts force control limits

**Purpose:** Start with weak gains (easier to control), gradually increase (harder task).

---

### 7. **Advanced Curriculum Parameters**

```bash
--upper_ratios 0.9 0.9 1   # Max gain multipliers: kp, kv, force_range
--lower_ratios 0.8 0.8 1   # Min gain multipliers: kp, kv, force_range
--curr_rew_thres 0.6 0.01 0.01 0.01  # Task, contact, imitation, BC reward thresholds
--aux_reset_thres 0 0 0    # Auxiliary reset thresholds: contact, imitation, BC
--deque_len 30             # Reward history length for curriculum decisions
--skip_grad                # Skip gradient-based curriculum updates
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--upper_ratios` | float list | `[0.9, 0.9, 1]` | Max multiplier per gain: how high gains can go |
| `--lower_ratios` | float list | `[0.8, 0.8, 1]` | Min multiplier per gain: minimum allowed value |
| `--curr_rew_thres` | float list | `[0.6, 0.01, 0.01, 0.01]` | Reward thresholds to trigger curriculum updates |
| `--aux_reset_thres` | float list | `[0, 0, 0]` | Extra reset conditions: contact, imitation, BC |
| `--deque_len` | int | 30 | Window size for reward smoothing |
| `--skip_grad` | flag | ON | Don't use gradient information in curriculum |

---

### 8. **Early Reset & Termination**

```bash
-ert 0.6                   # Early reset threshold
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `-ert` / `--early_reset_threshold` | float | 0.6 | Reset episode if reward drops below 0.6 × moving average |

**Purpose:** Escape bad episodes early, focus on successful trajectories.

---

### 9. **Object & Physics**

```bash
--actuate_object           # Enable object actuation (agent controls object directly)
--group_collisions         # Smart collision grouping to avoid self-collisions
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--actuate_object` | flag | ON | Agent controls object joints (articulated manipulation) |
| `--group_collisions` | flag | ON | Enable self-collision filtering by link groups |

**Impact:** With `--actuate_object`, agent learns to move the object in addition to hand control.

---

### 10. **Dialback (Late-stage fine-tuning)**

```bash
--dialback_ep_len 80       # Episode length during dialback phase
--skip_grad                # (Also used here) Skip gradient updates during dialback
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `--dialback_ep_len` | int | 80 | Longer episodes in late training for polishing |
| `--skip_grad` | flag | ON | Skip curriculum gradient updates (use simpler rules) |

---

### 11. **Logging & Experiment**

```bash
-exp example               # Experiment name
```

| Arg | Type | Value | Meaning |
|-----|------|-------|---------|
| `-exp` / `--exp_name` | str | `example` | Experiment suffix (appears in logs and WandB) |

**Output directory:** `logs/rl_games/<hand>/allegro-example_box30-230-s01-u01_B4096_hybrid.../`

## Anatomy of the Full Command

```bash
python dexmachina/rl/train_rl_games.py \
    # Parallelization
    -B 4096 \
    
    # Observations
    -obf -obt \
    
    # Training duration & schedule
    --max_epochs 10 \
    --horizon 16 \
    --learning_rate 0.0003 \
    --save_freq 500 \
    
    # Object control & collisions
    --actuate_object \
    --group_collisions \
    
    # Retargeting & demo data
    --retarget_name para \
    --use_retarget_contact \
    
    # Rewards
    -imi 0.3 \
    -bc 0.3 \
    -con 3 \
    --contact_beta 10 \
    --task_rew_betas 10 1 5 \
    --action_penalty 0.01 \
    
    # Curriculum (gains progression)
    --curr_schedule uniform \
    --wait_epochs 100 \
    --fixed_mode uniform \
    --gain_mode all \
    --uniform_mode slow \
    --upper_ratios 0.9 0.9 1 \
    --lower_ratios 0.8 0.8 1 \
    --deque_len 30 \
    --skip_grad \
    
    # Early reset & thresholds
    -ert 0.6 \
    --curr_rew_thres 0.6 0.01 0.01 0.01 \
    --aux_reset_thres 0 0 0 \
    
    # Action space
    -am hybrid \
    --hybrid_scales 0.1 1.0 \
    
    # Gains initialization
    --kp_init 80 \
    --kv_init 5 \
    
    # Fine-tuning
    --dialback_ep_len 80 \
    
    # Demo clip & experiment
    --clip box-30-230 \
    -exp example
```

## Common Modifications

### For Smaller GPU Memory
```bash
# Reduce batch size
-B 512          # Instead of 4096
-B 1024         # Medium
-B 2048         # Large
```

### Faster Learning (More Aggressive)
```bash
# Increase imitation weight, reduce curriculum wait
-imi 0.5        # Was 0.3
--wait_epochs 50  # Was 100
--learning_rate 0.0005  # Was 0.0003
```

### Slower, Stabler Learning
```bash
# Reduce rewards, increase curriculum wait
-imi 0.1
-con 1
--wait_epochs 500
--curr_schedule fixed  # No progression
```

### No Curriculum (Flat Difficulty)
```bash
--curr_schedule fixed
--wait_epochs 0
--curr_rew_thres 0 0 0 0
```

### Resume from Checkpoint
```bash
# Add this line
--checkpoint logs/rl_games/<hand>/<exp_name>/nn/<hand>.pth
```

## Troubleshooting

### Out of GPU Memory
- Reduce `-B` (batch size)
- Reduce `--horizon` (episode length)
- Reduce `--num_envs`

### Training too slow
- Increase `-B` (if memory allows)
- Increase `--learning_rate` (0.0003 → 0.0005)
- Reduce `--wait_epochs` (curriculum starts sooner)

### Agent not learning
- Increase `-imi` (imitation weight)
- Reduce `--action_penalty` (less smoothness penalty)
- Check retarget data exists: `assets/retargeted/allegro_hand/s01/box_use_01_vector_para.pt`

### Early resets too frequent
- Increase `-ert` threshold (0.6 → 0.8)
- Reduce early reset sensitivity: `--aux_reset_thres 0.1 0.1 0.1`
